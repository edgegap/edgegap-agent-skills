# BR200 specifics

Read from the BR200 2.1.0 source (`Assets/TPSBR/Scripts`).

## 1. How BR200 starts a server

`TPSBR.Loader` (scene `TPSBR/Scenes/Loader`, first in the build) checks `Application.isBatchMode`:
- In batch mode, `StartBatchGame()` copies the inspector's `_batchModeConfiguration` (a `StandaloneConfiguration`), overrides it from the command line, hands it to `StandaloneManager.ExternalConfiguration`, and loads the **Batch Mode Scene** (`GenArea7` by default) or `-scene`.
- Otherwise it loads the Menu.

The inspector defaults are `GameMode: Client` with `ExtraPeers: 9`: a batch build without flags starts ten test clients. `-dedicatedServer` switches to `GameMode.Server` and forces `ExtraPeers` to 0. `StandaloneManager.Start()` builds a `SessionRequest`, and `Networking.ConnectPeerCoroutine` turns it into `StartGameArgs`:
- `IPAddress` set: `Address = NetAddress.CreateFromIpPort(IPAddress, Port)`, the bind address.
- otherwise, if `Port > 0`: `Address = NetAddress.Any(Port)`.
- `CustomPublicAddress` is never set.
- `CustomLobbyName`: `-lobby`, or `FusionBR.<Application.version>`.
- `FixedRegion`: the configuration's `Region`. When it's empty, Fusion pings and picks the best region.

## 2. Command-line options

From `TPSBR.ApplicationSettings`. BR200 reads the **first** copy of a repeated option, so pass each one once.

| Option | Effect |
|---|---|
| `-dedicatedServer` / `-host` / `-client` | Game mode |
| `-battleRoyale` / `-deathmatch` / `-elimination` | Gameplay type (the Loader default is Deathmatch) |
| `-sessionName <name>` | Session name (`random` makes a GUID) |
| `-serverName <name>` | Display name in the session list |
| `-region <code>` | Photon region |
| `-maxPlayers <n>` | Player count |
| `-extraPeers <n>` | Extra local client peers (test only) |
| `-lobby <name>` | Custom lobby |
| `-scene <name>` | Map scene instead of the Batch Mode Scene |
| `-ip <address>` / `-port <n>` | **Bind** address and port (`fusion.md` §2) |
| `-fps <n>` | Frame rate |
| `-recordSession` / `-dataPath <dir>` | Session stats file and where it goes |
| `-generateInput` | Bots-style random input (handy for test clients) |
| `-stripped` | Stripped batch client |
| `-randomDeviceID` / `-deviceID <id>` | Player identity for several clients on one machine |

The kit's `edgegap/start-server.sh` passes `-batchmode -nographics -logFile - -dedicatedServer -ip 0.0.0.0 -port <internal> -sessionName <fqdn> -serverName <fqdn> -maxPlayers <n> -region <code>`, plus the optional ones from `BR200_*` variables. It refuses `BR200_EXTRA_ARGS` that would override them.

## 3. Project facts

- BR200's Project Settings enable unsafe code, set the Server and Standalone backends to IL2CPP, and set Peer Mode to Single.
- Build scenes: `Loader` (first), `Menu`, `LoadingScene`, `Game`, `GameplayUI`, `GenArea2`, `GenArea3`, `GenArea5`, `GenArea7`. BR200 ships with `Template.unity` **not** in the build, so "every scene in TPSBR/Scenes" is wrong. The kit's preflight checks only for the scenes BR200 loads and at least one map.
- Battle Royale starts a **120-second waiting timer** when the server boots (`BattleRoyaleGameplayMode._waitingForPlayersTime`). Players who join after it count as eliminated, so deploy when the group is ready and connect at once.
- When a Battle Royale is left with one player, that player gets Game Over and the server exits. With restart policy `never`, or the kit's self-stop call, the deployment then ends on its own. Measured: 156 s from deploy to `TERMINATED` with two players, one of whom left.
- A server build with the Server subtarget leaves the editor's standalone subtarget on Server. The next plain Windows build then came out headless and Mono. The kit's builder restores the subtarget, and the test client build sets `StandaloneBuildSubtarget.Player` explicitly.

## 4. Headless test clients

```
Client.exe -batchmode -nographics -client -extraPeers 0 -sessionName <fqdn> -region <code> -generateInput -logFile client1.log
```

- Always pass `-extraPeers 0`, or each process starts ten clients.
- Two processes on one machine work. Each got its own player in the tests.
- Success in the log: `StartGame() Result: [StartGameResult: Ok:True ...]`, then probe lines (`fusion.md` §6). Failure: `ShutdownReason: GameNotFound` (session, region, App Version or App ID mismatch, or the server isn't running).
- Kill one client to end a two-player Battle Royale. The other logs `StopGameOnDisconnect()` after its Game Over view.

## 5. Writing BR200 setup steps for people (Photon's docs, a guide)

Use the Loader inspector and keep the code change small:
- Loader **IP** `0.0.0.0` (or empty), **Port** 7777, Game Mode Server, Extra Peers 0.
- In `Loader.StartBatchGame()`, before `StandaloneManager.ExternalConfiguration = _batchModeConfiguration;`, set `ServerName` and `SessionName` to `$"{Environment.GetEnvironmentVariable("ARBITRIUM_REQUEST_ID")}.pr.edgegap.net"`, only when the variable is set.
- Don't anchor instructions to line numbers. They move between BR200 versions.
- Tell readers to press **Tab** and check CT shows Direct.
- Or skip the code change and use the kit, which does the same through the command line.
